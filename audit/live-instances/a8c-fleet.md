# Live instance: a8c-agents fleet (orchestrator → broker → 4 specialists → Brain)

**Territory:** `~/a8c-agents` — 9 coordinated launchd services (5 model workers + Brain Core + control broker + attention collector + proactive scheduler), 4 bespoke TypeScript packages (`brain-core`, `control-broker`, `attention-collector`, `gws-a8c`), a 3,763-line lifecycle manager (`bin/agents`), and a 7,754-line / ~266-case test suite. Cross-checked by verifier cluster V9 (Part B): every cited byte-count, line number, and log-grep count was independently reproduced, several strengthened by re-checking at a later timestamp. **Zero freeze-blockers** — both the auditor and the verifier mark every actionable row here `Freeze-blocking: n`.

## 1 Overview & grades

**Instance maturity grade: B+ (verifier: unchanged).** This is the single most sophisticated real deployment of mono-agent observed in this audit, and its documentation (`README.md`, `docs/architecture.md`, `docs/runbook.md`, `docs/migration.md`) is exhaustive, internally consistent, and — rare for a live system — matches what the code and logs actually do. The verifier reproduced every headline number exactly at a later re-check: real, growing production usage two days-plus post-migration (76 delegation-ledger tasks and 111 acknowledged results, up from 75/110 at first inspection), and the fleet's worst live incident — Brain Core crash-looping 108 times on a bad credential — is grep-exact (`grep -c` on the failure string returns 108, matching lines 45–152) and independently correlated to a backup the integrity verifier *correctly* rejected in the same window. The grade is capped at B+, not A, because the fleet has zero automated crash-loop protection anywhere in its 9-service launchd surface (F1) and ~1.5 GB of dead weight from three retired agents with no soak-period end date (F7) — both real, if non-catastrophic, operational gaps.

**Framework-fit grade: C+ (verifier: endorsed, with the caveat that the underlying gaps are architectural observations, not framework defects).** The low-level primitives mono-agent advertises — config-first agent folders, `cron/*.md` authoring, native `notify`, the sandbox, the A2A adapter as a transport, Slack's native adapter — are all used cleanly and exactly as designed (the three `orchestrator/cron/*.md` briefings are simple and idiomatic). But the moment this instance needed multi-agent *reliability guarantees* or a *shared knowledge base* — the two things the v1 premise explicitly promises ("crons, webhooks, and channels easily," "clean memory") — it had to build almost everything itself. The verifier's language for this is precise: F2 (memory), F3 (A2A reliability), and F4 (fleet tooling) are each re-labelled "architectural observation, not defect" — substance confirmed, but explicitly not framework bugs. C+ reflects that split: primitives fit, guarantees don't yet exist to be fit against.

## 2 What the fleet proves about the framework

- **The primitives compose cleanly at production scale.** Five independent agent folders (`orchestrator`, `attention-radar`, `delivery-copilot`, `deep-research`, `knowledge-steward`) each run config-first from `mono-agent.config.json`, author their own `cron/*.md` briefings, and route all outbound Slack/notification traffic through the framework's native `notify` path and Slack adapter — no bespoke transport layer was needed for any of that.
- **The A2A adapter holds up as a transport.** `@mono-agent/a2a-adapter` carries every inter-agent delegation call in this fleet; the instance only had to add reliability semantics on top (durable claims, outbox, reconciliation — see §3), not replace the transport itself.
- **The fleet fails loud and self-heals rather than faking success.** The 108x Brain Core crash loop was fully visible in logs (nothing was masked); the backup-integrity verifier correctly rejected an invalid snapshot during the same incident window; `control-broker.log` correctly flags `"degraded":true` on every cycle an outbox item is overdue. The gap the audit found is *paging*, not *detection* — the fleet's own instrumentation is honest even where nothing yet acts on it.
- **Real, growing usage two-plus days post-migration** — the verifier's re-check found delegation/ack counts *higher* than the auditor's first pass (76/111 vs. 75/110), confirming this is a live, actively-used deployment, not a demo.

**Freeze-blocker candidates explicitly considered and rejected** (not because the underlying findings are false, but because neither rises to a v1 DoD violation): F1 (108x crash loop) is bespoke instance `bin/agents` plist policy, not the framework's own launchd path; F9 (stuck outbox item) is a retryable, correctly-flagged-`degraded` alerting gap, not data loss or silent failure. Both instances — this one and the personal-agent sibling — independently surface the same cross-cutting theme the verifier calls out for synthesis: **mono-agent ships no honest-ops observability primitives** (log-rotation/size caps, crash-loop breaker, channel-health, delivery-SLO alerting). That theme, not any single finding here, is the one item worth carrying forward as a unified framework recommendation rather than six separate instance nits.
