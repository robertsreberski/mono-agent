## Rejected freeze-blockers

- **A5-1 (`restart --force` does not clear the durable conversation-history store; #203)** — REJECTED as blocker, downgraded to non-blocking **P2**. The finding is factually correct (default-on durable history at `<artifacts.dir>/../history`, no purge command exists). It is rejected as a blocker because: (1) the CLI message "Cleared persisted sessions" is literally accurate about what it clears (pi-native sessions) — history is a distinct store, so this is partial-truth/omission, not a false success claim; (2) it is a one-day-old feature (0.11.0, 2026-07-14) with an OPEN, Robert-triaged **P2** tracking issue (#203) whose "explicit operator command to clear sessions/history" bullet already owns this gap; (3) no correctness/secret/license catastrophe. Recommend the cheap pre-freeze mitigation (qualify the CLI message) even if the `purgeHistory` command lands post-freeze under #203.

## Cross-artifact cross-checks

- **A4-F2 (#201) vs A5-F1 (#203)** — no contradiction. #203's body explicitly states "This is separate from #201." A4 covers *proactive tool sends never entering destination history*; A5 covers *durable history never being cleared*. Complementary, consistent.
- **A4 (native notify:true records history via `app.ts`) vs A5-F1 (history not cleared)** — consistent: native-notify writes into the same durable store A5 says lacks a purge command. Together they imply the durable history accumulates from native-notify but not from the proactive send tools (#201) — a coherent, non-conflicting picture.
- **A4-F5 and A5-F5** both flag oversized files in `packages/agent-app` (`channels.ts` 1550; `continuation-service.ts` 2001 / `continuation-store.ts` 1615). Consistent legibility theme; both correctly non-blocking/post-freeze.

## NEW findings discovered during re-read

- **NEW-1 (reinforces A6-F5, P3→informational).** `config-reference.ts:896`'s `inferType` regex is case-insensitive over bare suffixes (`…port|dim|Runs|Days…/iu`), so the mis-typing failure mode is worse than "unusual name defaults to string": a future field id ending in e.g. `export` matches `port$`→**integer**, `medium`… no, but `…dim`→integer, `…runs`→integer. Any A6-5 fidelity test must therefore assert exact expected types per id (as A6-5 already specifies), not merely re-snapshot the generator. Folded into A6-F5; not a standalone new defect (no current field is mis-classified — verified against the committed schema).
- **NEW-2 (reinforces A5-F1, contextual).** `restart --force`/`purgeSessions` also leaves the durable *continuation ledger* (`.mono-agent/continuations/`) and memory untouched — i.e. "sessions" is narrower than an operator likely reads it. Continuation-ledger retention is plausibly intentional (dropping it would abandon in-flight continuation obligations) and memory retention is explicitly by design, so this is not a separate defect, but it strengthens the case that the CLI message should be qualified (per A5-1 mitigation) rather than left ambiguous.
