# 05 · Continuations, sessions & run history

**Scope:** agent-app durable continuation subsystem, sessions purge, run history, runs-health, artifact retention, request-model-override (13 files, `packages/agent-app/src/{continuation-service,continuation-store,continuations,continuation-config,continuation-command,sessions,run-history,runs-health,audit-runs,artifact-retention,backfill,metrics,request-model-override}.ts`). **Maturity grade: B+ (verifier-adjusted).** The durable-continuation subsystem is the most rigorously engineered code in this audit pass — content-addressed origin-context snapshots, HMAC domain-separated bindings, atomic bounded recovery, an independently-verified fail-closed v2→v3 rollback guard, and a lease/settlement state machine that refuses to guess at ambiguous outcomes. The grade is held back not by any freeze-blocker (the verifier confirmed none in this part) but by an "honest ops" gap in `restart --force` (partial-truth CLI message, tracked by open issue #203), thin test coverage on the operator-facing `runs-health.ts`, and two files (2,001 and 1,615 lines) that strain the "lean, understandable core" premise despite unusually good internal documentation.

## Findings

**F1 — [P2 after verification] [verifier: AMENDED]** — `packages/agent-app/src/sessions.ts:26-42`, `packages/agent-app/src/cli.ts:4278-4281`. `mono-agent restart --force` prints "Cleared persisted sessions" but `purgeSessions()` only resolves and deletes `resolveAppSessionsRoot` (the pi-native JSONL session store); it never touches the durable conversation-history store added in v0.11.0 (`configured-agent.ts:430-431`, `createDurableHistoryStore` at `resolvePath(config.artifacts.dir, "..", "history")`). Originally flagged P1 (unmet DoD bullet of open issue #203); the verifier confirmed the finding is factually real — `grep -riE "purgeHistory|clearHistory|resetHistory|purge.*history"` across `packages/agent-app/src` and `packages/agent-harness/src` (excluding tests) returns zero, so no operator command clears this store — but downgraded severity to **P2** and rejected it as a freeze-blocker: the CLI message is literally accurate about what it clears (pi-native sessions), the durable-history store is a distinct, one-day-old feature with its own OPEN, Robert-triaged P2 tracking issue (#203) that already owns this gap, and there is no correctness/secret/license catastrophe. `docs/runtime/sessions-concurrency.md:31`'s boundary-rules table was also not updated when the durable-history feature landed (commit `c2fccfe5`).
  ```ts
  export async function purgeSessions(input: MonoAgentAppConfigInput): Promise<PurgeSessionsResult> {
    const root = await resolveAppSessionsRoot(input);
  ```
  Verifier NEW-2 (contextual, folded into F1): `restart --force` also leaves the durable continuation ledger (`.mono-agent/continuations/`) and memory untouched — "sessions" reads narrower than an operator likely expects, even though continuation-ledger and memory retention are plausibly intentional by design. This strengthens the case for qualifying the CLI message rather than leaving it ambiguous.

**F2 — [P2] [verifier: CONFIRMED]** — `packages/agent-app/src/runs-health.ts:1-204`, `packages/agent-app/src/__tests__/runs-health.test.ts`. `runs-health.ts` implements stale-running detection, owner-gone detection, user-cancelled-vs-other-cancelled distinction, failure-kind histograms with human explanations, and relative-age formatting — the "honest ops" surface operators read via `mono-agent status`/doctor summaries — but the test file contains exactly **one** test (the "user cancellation does not degrade health" case). `isStaleRunningRun`, `runningWhileOwnerGone`, the failure-kind histogram/description path, `formatRelativeAge`'s minute/hour/day boundaries, and the `hasWarnings` aggregation are all untested. Verifier notes this is a coverage gap, not a demonstrated active bug. Why it matters: an off-by-one in the stale-running threshold or histogram sort would silently misreport agent health with nothing to catch it — a missing-test-coverage-of-load-bearing-behavior gap per the audit brief.

**F3 — [P2] [verifier: CONFIRMED, cross-territory]** — `packages/agent-app/src/artifact-retention.ts:1-162` (in scope); `packages/agent-app/src/launchd.ts:132-135` and `doctor.ts` (adjacent, cited as evidence). The framework has no bound on the raw process stderr/stdout stream that produces the reported 1.23 GB rotated err log; only recorded run artifacts (`*.summary.json`/`*.events.jsonl`) are retention-bounded via `pruneRunArtifacts` with sane defaults (`DEFAULT_ARTIFACT_RETENTION_MAX_AGE_DAYS = 365`, `DEFAULT_ARTIFACT_RETENTION_MAX_COUNT = 50_000`). `launchd.ts` generates plists with `StandardOutPath`/`StandardErrorPath` pointed at plain files with no companion rotation, and `doctor.ts` has no check for on-disk log size. Verifier confirms this as a genuine framework gap (primary ownership belongs to the deployment/launchd audit part) — not freeze-blocking, but real: mono-agent has a mature, tested bounding story for run artifacts but nothing for the one log surface most likely to grow unbounded from provider-SDK noise and retries.
  ```xml
  <key>StandardOutPath</key>
  <string>${escapeXml(input.stdoutPath)}</string>
  ```

**F4 — [P3, leans won't-fix] [verifier: AMENDED]** — `packages/agent-app/src/continuation-store.ts:299-350`. A fresh (never-migrated) continuation state directory unconditionally gets a legacy `records-v2` directory containing only the fail-closed `UPGRADED-TO-RECORDS-V3` rollback-guard file, even on a brand-new install with no prior v2 records. Originally framed as a stale migration artifact / dead-artifact nit. The verifier amended this: it is defensible defense-in-depth, not a defect — proactively poisoning `records-v2/` means a later rollback to v0.10 against this directory fails closed rather than silently reading a stale/absent snapshot. Keep as a P3 legibility nit at most; reasonable to close as WAI (working as intended) rather than fix.
  ```ts
  const legacyRecordsDir = join(stateDir, LEGACY_RECORDS_DIRECTORY);
  await ensureOwnerOnlyDirectory(recordsDir);
  ...
  await ensureOwnerOnlyDirectory(legacyRecordsDir);
  ```

**F5 — [P3] [verifier: CONFIRMED]** — `packages/agent-app/src/continuation-service.ts:236-1653` (2,001 lines total), `continuation-store.ts` (1,615 lines). `ContinuationService` is a single class mixing HTTP routing (`handleRequest`), lease/dispatch scheduling (`startDueJobs`/`processOne`), origin-context settlement (`requiresOriginContext`/`finalizeOriginContext`/`activateOriginContext`/`abandonOriginContext`), and the full operator/detached/claim protocol surface. Verifier confirms line counts (`wc -l` = 2001 / 1615) and scopes this as a legibility/altitude item, correctly non-blocking. Why it matters: not a bug, but a future maintainer changing lease semantics has to hold the whole state machine (10 `ContinuationState` values × 3 origin-context policies × claim/detached/operator auth paths) in their head at once — worth a post-freeze refactor into cohesive submodules (http-routes / dispatch-worker / origin-context / store).

## Quarantine (refuted/unproven)

- **A5-1 as freeze-blocker** — REJECTED as blocker (finding itself stands, downgraded to non-blocking P2, see F1). Reasons: (1) the CLI message "Cleared persisted sessions" is literally accurate about what it clears (pi-native sessions) — the durable history is a distinct store, so this is partial-truth/omission, not a false success claim; (2) it is a one-day-old feature (v0.11.0, 2026-07-14) with an OPEN, Robert-triaged P2 tracking issue (#203) whose "explicit operator command to clear sessions/history" bullet already owns this gap; (3) no correctness/secret/license catastrophe results.
- **`records-v2` fresh-install directory as "dead artifact" / dead code** — REFUTED as dead code. The verifier determined this is live code creating an intentional fail-closed artifact (poisoning `records-v2/` so a v0.10 rollback against the directory fails closed rather than reading a stale/absent snapshot), not a stale byproduct to be deleted. Do not remove this behavior on the assumption it is dead — it is deliberate rollback-safety defense-in-depth (F4, amended).
