# 12 · Observability

**Scope:** `@mono-agent/observability` — the shared run-recording, redaction, OTLP/Phoenix export, and trace-source/session-replay substrate consumed by agent-app, agent-harness, tui, and session-web. **Maturity grade:** B+ (verifier-adjusted — unchanged from raw; every finding CONFIRMED, none refuted, none escalated to freeze-blocking).

One of the most carefully engineered packages in the repo: path-traversal-safe file I/O, atomic writes, deterministic idempotent OTLP ids, a documented and tested `includeSensitiveData` gate, honest failure-kind derivation with no fake-success paths, and a fuzz-like test suite for the trace-source state machine. All 250 unit tests pass, build/typecheck are clean, and dead-code claims (there were none) held up under adversarial re-check. It loses grade points for two "honest ops" precision gaps rather than any fabricated result or shipped secret: a mid-run crash loses its whole event trail (the exact scenario its own `process_death` reconciler targets), and redaction is field-key-based only — free-text content is never content-scanned, which is live today on the flagship `personal-agent` instance running `includeSensitiveData: true`. Neither is freeze-blocking.

## Findings

1. **[P2 — should fix] [verifier: CONFIRMED]** — `packages/observability/src/recorder.ts:81-89` (also `:77-79` start(), `:122-127` commitTerminal). A run that crashes between `start()` and `finish()`/`fail()` loses its entire event trail; the persisted artifact reports `eventCount: 0` regardless of how much actually happened. `onEvent` only pushes into an in-memory array — the only two calls to `writeArtifacts` are inside `start()` (writes an empty `.events.jsonl`) and inside `commitTerminal()` (the terminal finish/fail). `reconcileStaleRunArtifacts` (`recorded-runs.ts:121-176`) exists specifically to reclaim runs whose process died mid-run and rewrites their status to `interrupted`/`process_death` — but for exactly that run, the on-disk event trail is whatever `start()` wrote (empty). `agent-app/src/broadcast-recorder.ts:22` notes the on-disk recorder "flushes only at start/finish" and compensates with a live in-memory broadcast for TUI/web — but that only helps a client watching *live*; it does nothing for offline/post-mortem forensics of an unwatched crash, which is the scenario the feature exists for.

    ```ts
    onEvent(event: RuntimeEventLike): void {
      if (this.terminalPromise !== undefined) return;
      const redacted = redactJsonValue(event, this.maxStringBytes) as RuntimeEventLike;
      this.events.push(...)
    ```

2. **[P2 — should fix] [verifier: CONFIRMED]** — `packages/observability/src/redaction.ts:40` (pattern at `:12`; `recorder.ts:63-68,135-138`). Redaction is field-key-based only; free-text fields are never content-scanned for embedded secrets, and this is live today on the flagship instance with `includeSensitiveData: true`. `redact()` only redacts when a JSON object *key* matches `SENSITIVE_KEY_PATTERN` (`/(token|secret|password|authorization|api[_-]?key|cookie)/iu`). Called on a bare string with no key, it falls straight to `truncateString`. `userInput` and the compiled `systemPrompt` are only ever truncated, never scanned for secret-shaped content (e.g. a tool echoing a `.env` file or an inline API token). Verified read-only, live: `~/personal-agent/mono-agent.config.json` sets the Phoenix exporter's `includeSensitiveData: true` against a loopback endpoint (`http://127.0.0.1:6006/v1/traces`) — loopback bounds network exposure, but content still crosses the mono-agent process boundary into Phoenix's own storage/retention. Docs describing this as "redacted" overstate what a flat-string field actually gets.
    ```ts
    if (key !== undefined && SENSITIVE_KEY_PATTERN.test(key) && typeof value !== "number") {
      return "[redacted]";
    }
    ```

3. **[P3 — legibility] [verifier: CONFIRMED]** — `packages/observability/README.md:37-48` vs `src/index.ts:1-168`. The package README's "Public API" list omits roughly a third of what `index.ts` actually exports, including the entire session/TUI-replay substrate: `mapRunToSession` and the `Session*` type family (`session-mapping.ts`, 1028 lines), `segmentTimelineTurns`, `summarizeRecordedRunMetrics` and its report types, `describeRunFailureKind`/`KNOWN_RUN_FAILURE_KINDS`, `RUNS_HEALTH_STALE_RUNNING_MS`, `reconcileStaleRunArtifacts`, `deriveRunSource`, `spanStatusFor`. Verifier independently spot-checked 7 of these exports present in `index.ts` and absent from README — all are real, consumed exports (grep-confirmed against agent-app/agent-harness/tui/session-web), not speculative surface. A competent stranger reading the README would not discover this package is the shared substrate for session replay and run-health/metrics reporting across three other packages.

4. **[P3 — nice to have] [verifier: CONFIRMED (plausible)]** — `packages/observability/src/artifact-fs.ts:91-96`. `writeJsonAtomic`'s per-attempt temp file (`${filePath}.${pid}.${seq}.tmp`) is never swept if a write fails partway (e.g. `ENOSPC`, or a crash between `writeFile` and `rename`). No sweep path exists anywhere in the package. Low likelihood, low blast radius (a few stray files).

5. **[P3 — nice to have] [verifier: CONFIRMED (latent)]** — event buffers are triple-held with no shared cap: once in `JsonlRunRecorder.events` (`recorder.ts:41`), once in the composite recorder's own buffer (`composite-recorder.ts:49`), and once more inside the Phoenix exporter's closure (`otel/phoenix-exporter.ts:65`). Each buffer is unbounded. Not a live risk today — a "run" is one user turn, bounded to dozens–low hundreds of events — but worth capping if per-run event volume ever grows (e.g. very long agentic tool loops).

## Dead code & deprecation

**Dead code: none found — CONFIRMED by verifier.** Every export traced from `index.ts`, including the less-obvious ones flagged in F3 (`mergeTraceSources`, `pruneTraceSources`, `reconcileStaleRunArtifacts`, `summarizeRecordedRunMetrics`, `describeRunFailureKind`/`KNOWN_RUN_FAILURE_KINDS`, `RUNS_HEALTH_STALE_RUNNING_MS`, `deriveRunSource`, `segmentTimelineTurns`, `mapRunToSession`), has at least one real, non-test consumer in `agent-app`, `agent-harness`, `tui`, or `session-web` (repo-wide grep). Verifier independently spot-verified the F3-flagged exports are consumed and found no removal claims to contest.

`TraceSourceHandle.heartbeat()` has no explicit external caller (heartbeats fire only via the internal timer registered in `registerTraceSource`) but is correctly classified — by both the raw audit and the verifier — as an intentional escape hatch on a small typed handle, not dead code.

**Deprecation: none in scope — CONFIRMED.** The "legacy" language on `refineRunSource` (`session-mapping.ts:283`) and `deriveRunSource` (`run-source.ts:13-19`) is load-bearing backward-compatibility code for reading old on-disk summaries, not deprecated surface awaiting removal. No `@deprecated` markers exist in this package.

No suspected/unproven entries — the raw audit's dead-code sweep and the verifier's independent spot-checks agree fully.
