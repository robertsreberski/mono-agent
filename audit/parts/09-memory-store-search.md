# 09 · Memory store & search

**Scope:** `packages/memory/src/store/*` (SQLite persistence, schema, ranking, FTS, vector index, replay/canonical-graph CAS validation) and `packages/memory/src/search/*` (embedding providers, circuit breaker, legacy v1 brute-force vector index).
**Maturity grade:** B (verifier-adjusted — grade unchanged; both P1s the raw audit flagged were downgraded to P2 on verification, and no freeze-blocker survived).
One-paragraph verdict: the SQLite store's hybrid FTS+vector recall, CAS-validated replay/canonical-graph replacement, and embedding-provider circuit breaker are correct, well tested, and free of fake-success paths or swallowed errors. The two most serious-sounding findings — a missing column-migration path and a dead npm-published legacy vector index — are both real but were confirmed by the verifier to be non-blocking: the first is a latent footgun with no defect at HEAD (and the SQLite index is rebuildable from canonical markdown if it ever bit), and the second is dead code with zero runtime impact. Nothing in this territory blocks freeze.

## Findings

**F1 — [P2 after verification] [verifier: AMENDED, P1→P2] — schema migration has no column-evolution path; `CREATE TABLE IF NOT EXISTS` is a silent no-op on existing databases.**
`packages/memory/src/store/schema.ts:6` (and every table in the same function) uses `CREATE TABLE IF NOT EXISTS memories (...)` with no `ALTER TABLE`, no `PRAGMA user_version` check, and no test that opens a stale on-disk schema and asserts migration. `openMemoryDb()`'s migration loop (`db.ts:120-122`) only runs when `readOnly !== true`. Git history shows only additive new-table changes so far, so nothing has broken yet, but the first column added the "obvious" way (editing the inline `CREATE TABLE` string) would leave every pre-existing `memory.db` missing that column, throwing `SQLITE_ERROR: no column named X` on every write with no automated recovery (`rebuild()` at `db.ts:1006-1016` only does `DELETE FROM`, never DDL). Verifier confirmed all the underlying evidence but downgraded: this is a latent guardrail gap, not a defect at HEAD, and it is recoverable (the SQLite index can be rebuilt from canonical markdown). **Freeze-blocker rejected by verifier** — file as a P2 issue (header comment + regression test), not a v1 blocker.
```
`CREATE TABLE IF NOT EXISTS memories ( ... )`
```

**F2 — [P2 after verification] [verifier: AMENDED, P1→P2] — dead, npm-published "search" API: `VectorMemoryIndex`/`gatherMemoryChunks` have zero consumers and no deprecation notice.**
`packages/memory/src/search/vector-index.ts` (240 LOC) and `packages/memory/src/search/chunks.ts` (91 LOC) implement a full brute-force JSONL vector store and journal/entity chunk-gatherer from the pre-BuJo v1 memory system, fully superseded by the SQLite+sqlite-vec `MemoryDb`. Verifier re-ran the grep and confirmed **zero** consumers outside `packages/memory/` and outside `dist/`; `search/index.ts:13-14` re-exports it, `package.json` is `publishConfig.access: public`, and `README.md:198` lists it as current public API with no deprecation language. Verifier's correction: this is the same class of finding as the B1 territory's dead public-API finding (there rated P2), so B3's F2 is normalized to P2 for cross-artifact consistency rather than P1. **Freeze-blocker rejected by verifier** — dead code with zero runtime impact, not a secret/correctness/honesty issue; a P2 cleanup, not a blocker.

**F3 — [P2] [verifier: CONFIRMED] — `store/db.ts` is a 2,696-line file mixing four unrelated concerns.**
Combines the `MemoryDb` SQL persistence class (lines 92-1993), replay-projection CAS validation (~1995-2214), canonical-graph replacement CAS validation (~2216-2457), and ~220 lines of bespoke natural-language relation-direction heuristics for `expandEntityRelations` (2474-2673). Verifier confirmed `wc -l` = 2696 and rated this a legibility risk on the "lean, understandable core" premise, non-blocking, fixable as a pure-move refactor.

**F4 — [P2] [verifier: CONFIRMED] — embedding-provider error taxonomy is inconsistent: HTTP failures are typed, network/timeout failures are not.**
`packages/memory/src/search/embeddings.ts:276-284` (`withTimeout`) wraps every provider's `fetch` in an `AbortController` timeout with no `catch` — a timeout or connection failure (a common case for the two local-first providers, Ollama/LM Studio) produces a raw `DOMException`/`TypeError` instead of the package's typed `MemorySearchError`. No test exercises the timeout/network-failure path. Verifier confirmed the code and the gap: "honest ops" is not fully violated (the error still surfaces, just uncoded), non-blocking.

**F5 — [P3] [verifier: CONFIRMED] — endpoint validation is inconsistent across the three embedding providers.**
`LmStudioEmbeddingProvider` validates its endpoint through `normalizeServiceRoot` (`embeddings.ts:256-274`), rejecting non-HTTP(S) schemes and embedded credentials/query/fragment. `OllamaEmbeddingProvider` and `OpenAIEmbeddingProvider` only strip a trailing slash. Verifier confirmed `normalizeServiceRoot` is used only by LM Studio; low exploitability since endpoints are operator-supplied local config, not attacker input.

**F6 — [P3] [verifier: CONFIRMED] — `MemoryDb`'s constructor performs a filesystem write (`mkdirSync`) even when opened `readOnly: true`.**
`packages/memory/src/store/db.ts:107-109` runs `mkdirSync(dirname(options.path), { recursive: true })` unconditionally, before the `readOnly` branch is checked (`db.ts:110-113`). A read-only open against a missing parent directory will silently create that (empty) directory tree, then still throw on the subsequent `fileMustExist: true` open. Verifier confirmed the line numbers and the leak against this audit's own read-only-access constraint; a small, one-line-fix contract leak.

## Dead code & deprecation

**Proven:**
- **`packages/memory/src/search/vector-index.ts` (240 LOC) + `packages/memory/src/search/chunks.ts` (91 LOC)** — `VectorMemoryIndex`, `createVectorMemoryIndex`, `gatherMemoryChunks`, `EntityLike`. Verifier-confirmed dead: `grep -rln "VectorMemoryIndex\|gatherMemoryChunks\|createVectorMemoryIndex\|MemoryChunk" --include=*.ts packages extras demos scripts website | grep -v /dist/ | grep -v packages/memory/` returns empty; only self re-exports and types remain inside the package. `README.md:198` still advertises it as current public API. Disposition: delete, or mark `@deprecated` in source JSDoc + README if kept for external plugin authors.
- **`MemoryDb.applyDecay()`** (`store/db.ts:1979-1988`) — verifier-confirmed `@deprecated` no-op; spy-tested (`bujo/__tests__/reflect.test.ts`, `consolidate.test.ts`) to prove it is never called by current reflect/consolidate pipelines. Removable-now internally; kept only as external-package API compatibility (older direct consumers of `@mono-agent/memory/store` calling `applyDecay` get `{decayed: 0}` instead of a `TypeError`). Distinct from the unrelated `BujoMemoryStore.decay()` method flagged in the B2 territory — verifier explicitly confirmed these are different symbols, not double-counted.
- **`"about"` `MemoryEdgeKind`** (`store/types.ts:52`, `schema.ts:33` CHECK constraint, `db.ts:938` `expand()` traversal, `db.ts:1294/1313` canonical-graph read/wipe sets) — verifier-confirmed no writer anywhere (`grep -rn "'about'|\"about\""` filtered to insert/values/push/write returns nothing), cross-checked consistent with the B2 territory's independent flag of the same edge kind. `db.ts:1277-1278`'s own comment: "Canonical graph `about` edges are intentionally empty in v1." Disposition: either retire the kind from the type/CHECK constraint (needs its own migration, see F1) or document it as reserved/unused.

**Verifier-confirmed intentionally-inert (not dead, keep through v1):**
- `recency` field of `RecallWeights` and `decayGamma`/`DEFAULT_DECAY_GAMMA` of `MemoryDbOptions` (`store/types.ts:136,203,219,226`) — verifier confirmed: honestly commented ("do not feed it into the scorer"), not exposed through any agent-app config surface, tested via `decay.test.ts`. Explicitly **not** a dead-code claim — do not delete without a version bump decision.
