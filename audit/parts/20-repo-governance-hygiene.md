# 20 · Repo governance, dev tooling & git hygiene

**Scope:** dev-tooling surface (agent templates, skills, discoverability gate), epic/goal documentation honesty, git/worktree/branch hygiene, root README leanness, and stale build artifacts. **Maturity grade:** B- (verifier-adjusted). The automated parity/drift machinery this repo built for itself (`check-codex-discoverability.mjs`, `package-count-drift.test.mjs`) genuinely works and was independently re-verified; what pulls the grade down is uneven application of that same "keep the story honest" discipline — an epic DoD line whose defect is staleness/ambiguity rather than flat falsity, a stale (but never-followed) worktree path in one agent template, a git-hygiene regression with no automation to stop recurrence, a README that has grown past "lean," and a drift guard with one uncovered file. None of these rise to a freeze-blocking defect on adversarial review; all are real, worthwhile pre-freeze cleanup.

## Findings

### F1 — [P1] [verifier: AMENDED] — Epic #119's DoD package-count line is stale/ambiguous, not flatly false
`gh issue view 119` body, "v1 definition of done": "Package count ≤ 18 active, plugin seam documented with whatsapp as the worked example." The shipped catalog (`scripts/package-catalog.mjs`, `PACKAGES.md:5`, `README.md:144`) has 21 publishable packages (16 core + 4 plugin-tier extras + 1 unscoped `create-mono-agent` alias). A 2026-07-06 retro comment on #119 already corrected the arithmetic to "20" once, in a comment, but the checklist text itself was never edited, and the count has since grown to 21 (PR #198).
Verifier correction: under a *core-only* reading (16 ≤ 18) the line is arguably satisfied; under a *publishable-total* reading (21) it is not. **The real defect is ambiguity/staleness, not "definitionally false."** It is a real must-fix-before-closing-#119 doc edit, not a capability/correctness/secret catastrophe — verifier explicitly rejected this as a freeze-blocker (second key withheld).
> "Package count ≤ 18 active, plugin seam documented with whatsapp as the worked example."

### F2 — [P2] [verifier: AMENDED, deflated from P1] — `agents/implementer.md` cites a worktree path nobody follows
`agents/implementer.md:21` says worktrees go in `.claude/worktrees/<name>`; `skills/worktree-feature/SKILL.md:14-16` and live practice put all 44 active worktrees under `~/.config/superpowers/worktrees/mono-agent/…`; the stale path is also repeated in #119's own protocol body (item 9). `.claude/worktrees/` is excluded only via a personal, uncommitted `.git/info/exclude` line, not the shared `.gitignore`.
Verifier correction: the contradiction is real and confirmed (`git worktree list | grep -c .claude/worktrees` = 0), but the risk is **theoretical** — nobody currently follows the stale line, so it was deflated from P1 to P2 and explicitly rejected as a freeze-blocker.
> "In a worktree: `git worktree add .claude/worktrees/<name> -b <branch> origin/main`"
