# Fully Local Ollama Agent (No Cloud)

This playbook builds an agent that runs entirely on a local [Ollama](https://ollama.com) provider through the Pi SDK runtime, with journal memory backed by local embeddings and a sandbox that blocks all non-localhost network traffic. No cloud API keys, no outbound calls.

## Who this is for

A privacy-focused user with no cloud API budget who wants the whole stack — chat model, embeddings, and recall — to stay on their own machine.

## Goal

An agent that runs entirely on a local Ollama provider via the Pi SDK runtime, with journal memory using local embeddings and no outbound network.

## Features used

- [`runtime.local-providers`](../runtime/local-providers.md) — register Ollama as a `pi:<provider>:<model>` backend
- [`runtime.multi-backend`](../runtime/backends.md) — the Pi SDK bridge that drives the local provider
- [`memory.journal`](../memory/capture-and-recall.md) — hybrid (BM25 + vector) recall with decay, no LLM required
- [`memory.embeddings-config`](../memory/embeddings.md) — local Ollama embeddings for the journal tier
- [`sandbox.network-policy`](../tools/sandbox.md) — restrict runtime commands to localhost

## Configuration

Every key below is verified against [the config blueprint](../config/blueprint.md). The `providers.local[]` entry registers Ollama; `runtime.model` references it as `pi:ollama:gemma4:31b`. Journal memory needs an `embeddings` block, and `sandbox.network.mode: "localhost"` keeps all runtime command traffic on-box.

```json
{
  "runtime": {
    "model": "pi:ollama:gemma4:31b"
  },
  "providers": {
    "local": [
      {
        "id": "ollama",
        "type": "ollama",
        "baseUrl": "http://localhost:11434",
        "enabled": true,
        "models": [
          {
            "name": "gemma4:31b",
            "capabilities": { "context_window": 32768 }
          }
        ]
      }
    ]
  },
  "memory": {
    "mode": "journal",
    "path": "./.mono-agent/memory",
    "embeddings": {
      "provider": "ollama",
      "model": "nomic-embed-text:v1.5",
      "endpoint": "http://localhost:11434",
      "dim": 768
    }
  },
  "sandbox": {
    "mode": "native",
    "network": { "mode": "localhost" }
  }
}
```

Use the exact `nomic-embed-text:v1.5` tag — the bare `nomic-embed-text` name resolves to a different revision and will not match the stored 768-dim vectors.
{: .warning }

The journal tier is config-only and needs no `memory.llm`; recall is embeddings + FTS with no model call. Promote to `mode: "bujo"` later if you want LLM capture and rituals (which then require a `memory.llm` block). See [Capture and recall](../memory/capture-and-recall.md).
{: .note }

## Steps

1. Pull both models locally: `ollama pull gemma4:31b && ollama pull nomic-embed-text:v1.5`
2. Scaffold the agent: `mono-agent init --model pi:ollama:gemma4:31b --memory journal`
3. Add the `providers.local[]` entry for Ollama and the `memory.embeddings` block, then set `sandbox.network.mode` to `localhost`.
4. Run `mono-agent validate` to confirm Ollama is reachable and both models are pulled.
5. Run `mono-agent start` — keep the [webhook channel](../channels/webhook.md) as the zero-credential smoke channel.
6. `curl` the webhook endpoint and confirm a response generated by the local model.

## Smoke test

`curl -X POST` the webhook invoke path with a prompt; verify a response generated by the local Ollama model and that the run artifact shows no outbound non-localhost network.
{: .tip }
